REQUIREMENTS
------------

* РHP 8.2
* Node 22
* Composer 2


HOW TO RUN LOCALLY
------------

Чтобы запустить сайт локально, выполните инструкции:

1. скачайте этот репозиторий;
2. установите необходимые пакеты командой `npm i`;
3. запустите сервер `npm run serve`;
4. Перейдите в браузере на адрес веб-сервера http://localhost:8000
   - Dev-сервер PHP доступен на http://localhost:8080, BrowserSync проксирует его на http://localhost:8000 с автообновлением.

FILES
------

* src/pages/index.php — HTML код сайта
* src/pages/404.php — страница ошибки 404

РАЗРАБОТКА НА ШАБЛОНЕ
----------------------

Новые страницы
- Все страницы находятся в каталоге `src/pages` и пишутся на PHP (можно использовать обычный HTML внутри). Создайте файл `src/pages/имя_страницы.php` — он будет доступен по адресу `http://localhost:8000/имя_страницы`.
- Частичные шаблоны (partials), которые не должны попадать в итоговую сборку как отдельные страницы, называйте с подчёркиванием в начале: например, `_header.php`, `_footer.php`. Такие файлы можно подключать через `require`, и задача Gulp по сборке HTML их игнорирует.
- Роутер (`router.php`) автоматически:
  - обслуживает `index.php` по корню `/`;
  - ищет страницу по пути `src/pages/<route>.php`;
  - отдаёт `src/pages/404.php`, если файл не найден.

Где хранить и как подключать JS
- Исходники JavaScript лежат в `src/js`. Точка входа по умолчанию — `src/js/script.js`.
- В режиме разработки подключайте в страницах путь `/src/js/script.js`:
  `<script src="/src/js/script.js" defer></script>`
  Роутер подменяет его на собранный файл из `dist/js/script.js`.
- Сборка и бандлинг выполняются Webpack. Конфигурация: `webpack.config.js`. По умолчанию настроен один entry `script` → `dist/js/script.js`.
- Как добавить ещё один бандл:
  1) создайте `src/js/another-page.js`;
  2) добавьте новый entry в `webpack.config.js`:
     `entry: { script: './src/js/script.js', another: './src/js/another-page.js' }`;
  3) подключайте на нужной странице `/src/js/another-page.js` — роутер подменит на `/dist/js/another.js`.
- Вы также можете импортировать модули напрямую внутри `script.js` вместо добавления новых entry.

Где хранить и как подключать CSS/Sass
- Стили пишем на Sass в каталоге `src/sass`. Главный файл по умолчанию — `src/sass/style.sass` (можете использовать `.scss`, обновив импорты/ссылки при необходимости).
- В режиме разработки подключайте в страницах путь `/src/sass/style.sass`:
  `<link href="/src/sass/style.sass" rel="stylesheet">`
  Роутер подменяет его на скомпилированный CSS из `dist/css/style.css`.
- Компиляцией занимается Gulp: задача `gulp watch` следит за `src/sass/**/*.sass` и кладёт CSS в `dist/css`.
- Рекомендуемая структура:
  - `src/sass/style.sass` — точка входа, импортирует остальные partials;
  - `src/sass/blocks/_*.sass` — блоки/компоненты;
  - `src/sass/utils/_variables.sass`, `_mixins.sass` — утилиты.

Сборка и публикация
- JS production-сборка: `npm run build` (Webpack, минификация, source maps отключены).
- Полная подготовка артефактов: `gulp publish` — оптимизирует изображения, собирает HTML (конвертирует `src/pages/*.php` в статику в `dist/pages`), компилирует и пост-обрабатывает CSS.
- В CI можно использовать сценарий: `npm run build-in-pipeline` (скачивает зависимости, собирает JS, запускает `gulp publish`, затем `php build.php`).

Примечания
- Изображения складывайте в каталог `img/`. Команда `gulp publish` оптимизирует их на месте.
- Во время разработки храните пути к ассетам как к исходникам (`/src/...`) — роутер сам подменит их на `dist/...` при отдаче страниц.
